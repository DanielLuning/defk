# Changelog

## Version policy

- `0.0.x` was the research project: anything could change between versions.
- From `0.1.0`, the first version published to Hex, the
  [stability promise](docs/guides/stability.md) holds: within a major
  version (`0` counts as one) a valid kernel keeps compiling and keeps its
  meaning, and a change to the kernel subset, the runtime contract, the
  public API or the compile error codes needs a deprecation first. A minor
  version may add constructs, builtins and options. Each release lists here
  its bug fixes that change a result or reject a kernel, its deprecations,
  and any rise in the minimum Elixir or OTP version.

## Unreleased

- Changed (unstable API): the result cache of `mix defk.examples --bench`
  (`Defk.Bench.Cache`) is no longer in the package. It is the catalog
  runner's adapter, kept in the repo's `dev/` and loaded into each
  example's process by the runner. `Defk.Bench.report/1` is unchanged and
  measures every report when the adapter is absent, as `elixir
  examples/x.exs` always did. The quiet test moved to `Defk.Bench`:
  `wait_quiet/0`, `other_cpu/0`, `quiet?/1` and `quiet_limit/0`.
- Added: `Enum.reduce/3` in kernels, the same fold as `for ..., reduce:`.
- Added: `Enum.find/3` in kernels: the first element for which the `fn` is
  true, or the default. The default and the elements have one type.
  `Enum.find/2` and `Enum.find_index/2` stay rejected with the code
  `enum-find`, now outside the kernel subset for good (they return `nil`,
  which a kernel does not have), and the error points to `Enum.find/3`. The
  code `enum-reduce` now rejects only `Enum.reduce/2`, as before.
- Added: a kernel's `raise` message may interpolate integer values,
  `raise ArgumentError, "bad offset #{i}"`. Other values stay rejected with
  the code `raise-message`.
- Added: `Defk.Errors.diagnostics/1` reads the rejections of a compile
  error as data: each one's code, `error:` text, file, line, column, module
  and kernel. A tool that compiles kernels (an editor, an agent's retry
  loop, `Code.compile_string/2` at run time) no longer parses the message.
  Compile errors stay `CompileError`.
- Fixed: a rejected pipe and a `for ..., reduce:` whose init or generator
  is rejected now report the errors inside them in the same compile. The
  calls in a pipe are checked as written nested; a reduce body is checked
  with its accumulator poisoned, so nothing that only follows from the
  rejection is reported. The codes are the same.
- Fixed: an `operand-type` error's why matches its operands. Every such
  error said "booleans are not numbers", also for a negated `u64`, a float
  in a bitwise operator or a number in `and`. The code is the same.
- Changed (unstable API): a kernel generated by a macro that quotes with
  `location: :keep` has its fast-path report notes on the macro's source
  lines. In `__defk_report__/0`, a line in another file than the module's
  is `{file, line}`.
- Documented: `__defk_stats__/0` counts per loaded library; a reload that
  builds a new library starts its counters at zero.
- Fixed: a `@doc` written before a `defk` was lost, and moved to the next
  `def` of the module. It now documents the kernel's function, as `@impl`
  already did.
- The compile error catalogue lists the retired codes (`bitwise`,
  `module-attribute`, `read-only-array`, `tuple-return-call`,
  `array-accumulator`, all retired in 0.0.1) under "Retired", each with the
  version and why. `Defk.Errors.entries/0` returns them, marked retired.
- Faster: an `alloc/2` skips its zeroing in two more shapes where the next
  loop provably writes every element first: a `for ..., reduce:` whose
  clause body holds the writes (also as the right side of a match), and
  nested range loops writing a row-major index `(y * w + x) * ch + c` into
  an array of `h * w * ch` elements. The fast-path report notes them as
  before. Results are unchanged: the array was all zeros only where it was
  not written, and it is written everywhere.
- Runtime contract: the whole-buffer work a call does outside its loops no
  longer holds the scheduler. In a yielding kernel a value-semantics copy
  and the aligned copy of a misaligned input run in 1 MiB strips with a
  safepoint after each, like `alloc/2`'s zeroing (a 256 MB copy was a
  4-94 ms gap, now the ticker's floor). A bitstring result over 1 MiB is
  handed over instead of copied out, and a grown accumulator is zeroed a
  strip at a time, as the appends reach it, not all at once. A kernel with
  `yield: false` copies at once, as before, and so does a kernel without a
  loop. Growing an accumulator past tens of MB still reallocates it at once
  (64 MB: 10-17 ms); a chunked accumulator would need a design.
- Faster: a bounds or overflow check is left out where a condition proves
  it: inside an `if` or `cond` arm (a later `cond` arm also sees the earlier
  conditions false), after a `for` filter, on the right side of `and`, in
  the body of a range that runs, and after a raising guard,
  `if w < 1, do: raise(ArgumentError, "...")`. docs/language.md now
  recommends raising guards for what a kernel needs of its arguments. When
  a check stays, the fast-path report names a small fact that would drop
  it: `nothing proves i - w < length(x) (it would follow from w >= 0)`. An
  `if` value whose arm relies on its condition to drop a check is a branch,
  not a select. Results are unchanged.
- Faster: a row-major index with a runtime row length, `m[r * dim + j]`,
  keeps no bounds check when the row count comes from
  `n = div(length(m), dim)` or a raising guard states the shape
  (`if length(m) != n * dim, do: raise(...)`), and the product `r * dim`
  loses its overflow check where the same facts bound it. A kernel that
  used a literal row length (`@dim 384`) only to drop these checks no
  longer needs it. Results are unchanged.
- Faster: a call that allocates (an `alloc/2` result, a bitstring
  accumulator, a copy) no longer allocates and frees a table for its owned
  buffers; the first four slots live in the call's frame. A one-buffer call
  costs about half of what it did (a one-byte bitstring result 125 ns to
  60-70 ns, under load). Results and the runtime contract are unchanged.

## 0.1.0

The first release on Hex, after the project's verdict (go) and the release
readiness work.

- The kernel subset, described in `docs/language.md`, with Elixir mode: every
  kernel also compiles to plain Elixir, so tests can check the two agree.
- The runtime contract: preemption, isolation with fault containment,
  cleanup on process death, hot code upgrade.
- The compile error catalogue: every rejection has a stable code, why, a
  hint and a rewrite where one exists.
- The [stability promise](docs/guides/stability.md) for the kernel subset,
  the runtime contract, the public API and the error codes.
- Tested on every change on Linux x86-64 (clang and gcc), Linux arm64
  (clang) and macOS arm64 (Apple clang), with OTP 29 and Elixir 1.20.
- Fixed before the release: the operands of an operation are evaluated in
  Elixir's order, so the first error is Elixir's on every C compiler (gcc on
  x86-64 evaluated call arguments right to left); the `address` sanitizer
  mode builds with gcc; the sanitizer modes load with clang on Linux.

### Renamed before 0.1.0

The last renames before the stability promise freezes the names. There are
no deprecated aliases: the old names are gone.

| Old name | New name |
|---|---|
| builtin `len/1` | `length/1` |
| builtins `rotl64/2`, `rotr64/2`, and `Defk.Bits.rotl64/2`, `Defk.Bits.rotr64/2` | `rotl/2`, `rotr/2` |
| builtin `f64_to_u64/1`, and `Defk.Bits.f64_to_u64/1` | `f64_bits/1` |
| `use Defk, max_owned: n` (and the `__defk_stats__/0` key `max_owned`) | `max_owned_bytes: n` (`max_owned_bytes`) |
| `Defk.Errors.codes/0` | `Defk.Errors.entries/0` |
| compile error code `unknown-function` | `undefined-function` |
| compile error code `u64-mix` | `u64-with-i64` |
